Source: `basecamp/once-campfire` at `.context/once-campfire`. Files read: `config/routes.rb`, all of `app/controllers/**`, `app/channels/**`, `config/initializers/{turbo_streams_authorization,active_storage_authentication,session_store}.rb`, the broadcast-related models (`message/broadcasts.rb`, `room.rb`, `rooms/*`, `membership*.rb`, `user*.rb`, `webhook.rb`, `room/message_pusher.rb`), every `*.turbo_stream.erb` and `*.jbuilder`, the Stimulus controllers that talk to ActionCable, and `test/controllers` + `test/channels`.

Conventions used below:
- **Auth** means you must be signed in (cookie session). Anything else is stated explicitly.
- **Bot** means bot-key auth is allowed. Every other action returns `403` to a bot.
- **Admin** means `user.administrator?`. **Admin-or-creator** means `can_administer?(record)` (defined below).
- `Current.account` is always `Account.first`. The app is single-tenant.

## 0. Global request pipeline (ApplicationController)

`include AllowBrowser, Authentication, Authorization, BlockBannedRequests, SetCurrentRequest, SetPlatform, TrackedRoomVisit, VersionHeaders`

| Concern | Behavior |
|---|---|
| `AllowBrowser` | Blocks old browsers (Safari < 17.2, Chrome < 120, Firefox < 121, Opera < 104, any IE) by rendering `sessions/incompatible_browser`. **Drop.** |
| `Authentication` | `before_action :require_authentication` and `:deny_bots`. CSRF `protect_from_forgery with: :exception, unless: -> { authenticated_by.bot_key? }`. |
| `BlockBannedRequests` | For non-GET/HEAD requests: `head :too_many_requests if Ban.banned?(request.remote_ip)` (429). GET requests from banned IPs still go through. |
| `TrackedRoomVisit` | Reads and writes a plain permanent cookie `last_room` (room id). `last_room_visited = Current.user.rooms.find_by(id: cookies[:last_room]) \|\| Current.user.rooms.original` (`original` is the oldest room by created_at). |
| `VersionHeaders` | Sets `X-Version` and `X-Rev` response headers. **Drop.** |
| `SetCurrentRequest` | Builds URLs from the request's host and protocol. |

Authorization primitive (`User::Role`):
```ruby
def can_administer?(record = nil)
  administrator? || self == record&.creator || record&.new_record?
end
```
Called with no argument, it means "is admin". Called with a record, it means "admin, or creator of the record". `ensure_can_administer` (Authorization concern) returns `head :forbidden` unless `Current.user.can_administer?`. Several controllers override it with a record-aware version.

`RoomScoped` (used by Messages, Involvements, Refreshes):
```ruby
@membership = Current.user.memberships.find_by!(room_id: params[:room_id])  # 404 if not a member
@room = @membership.room
```

## 2. Authentication

### 2.1 Cookies and sessions
- A **`sessions` table** stores `token` (`has_secure_token`), `user_id`, `user_agent`, `ip_address` and `last_active_at`.
- **Auth cookie `session_token`** is `cookies.signed.permanent[:session_token] = { value: session.token, httponly: true, same_site: :lax }`. The value is signed but not encrypted, and is permanent (20 years).
- Lookup is `Session.find_by(token: cookies.signed[:session_token])`. The same lookup authenticates ActionCable and Active Storage uploads.
- On resume, the session updates `user_agent`, `ip_address` and `last_active_at` only if `last_active_at` is more than 1 hour old. These session IPs are what `ban` uses to create IP bans.
- The Rails cookie session `_campfire_session` (`expire_after: 20.years`) holds only the CSRF token and `return_to_after_authenticating`.
- An unauthenticated request stores `session[:return_to_after_authenticating] = request.url` and redirects to `/session/new`.
- Logout destroys the Session row, resets the session, deletes the cookie, and disconnects the user's websockets.
- A banned or deactivated user has all sessions deleted, and their sockets are closed with no reconnect.
- **Note:** connection lookup does not check `user.active?`. Deleting sessions is what revokes access.

### 2.2 First run
`/` → `/session/new` → `/first_run` (redirects there while `User.none?`). `POST /first_run` creates the Account, the admin and the "All Talk" open room, then signs in. After that it is blocked by `Account.any?`.

### 2.3 Join by code
- The invite URL is `/join/<join_code>`. The code is `SecureRandom.alphanumeric(12)` split into 4-character groups joined by `-`.
- Admins can regenerate it (`POST /account/join_code`).
- A wrong code returns 404, and a signed-in visitor is redirected to `/`.
- Creating the user auto-joins all Open rooms and signs them in.

### 2.4 Session transfer ("sign in on another device")
- `user.transfer_id` is `signed_id(purpose: :transfer, expires_in: 4.hours)`.
- The URL `/session/transfers/<transfer_id>` is shown on your own profile and, for admins, on any user's page so they can help locked-out users.
- GET renders an auto-submitting PUT form. PUT starts a new session for that user.
- The link is reusable until it expires and is not single-use.
- Port idea: `Phoenix.Token.sign(endpoint, "transfer", user_id)` with `max_age: 4h`.

### 2.5 Login rate limit
`rate_limit to: 10, within: 3.minutes, only: :create` (per IP, Rails cache). Response is 429 with the login page.

### 2.6 Bot authentication and the exact bot API

**Key format:** `bot_key = "#{user.id}-#{bot_token}"`, where the token is 12 alphanumeric characters.
```ruby
def authenticate_bot(bot_key)
  bot_id, bot_token = bot_key.split("-")
  active_bots.find_by(id: bot_id, bot_token: bot_token)   # role: bot AND status: active
end
```
- `require_authentication` tries `restore_authentication || bot_authentication || request_authentication`, in that order.
- Bot auth uses `params[:bot_key]`, so **any** route accepts a `bot_key` (even as a query param). `deny_bots` then returns **403** unless the action used `allow_bot_access`; the tests confirm `GET /rooms/:id/messages?bot_key=...` → 403.
- CSRF is skipped when authenticated by bot key.
- An **invalid bot key results in a 302 redirect to `/session/new`** (falls through to `request_authentication`); the tests assert `:redirect`. A port should return **401**; that is an intentional, harmless deviation.
- Tests guard against `"#{human_id}-"` (empty token); the `active_bots` scope prevents a match. Port: reject an empty token and compare in constant time.
- Bots can only reach rooms they are members of: `Current.user.rooms.find_by(id: params[:room_id])`, else **404**. Bots join open rooms automatically (`grant_membership_to_open_rooms` on create) and other rooms through closed-room editing or DMs.

**Request bodies are raw:** (`RawRequestBody`: `request.body.read.force_encoding("UTF-8")`)
- **POST messages** accepts two formats:
  - **Raw body**, for example `curl -d 'Hello!' URL`. The content type is usually `application/x-www-form-urlencoded`, but it is ignored: the raw body becomes `message.body` and is interpreted as ActionText **HTML**, so HTML and mention `<action-text-attachment sgid=…>` tags work.
  - **Multipart** with an `attachment` file field (`curl -F "attachment=@/path/file" URL`) creates an attachment message with no body.
  - `params[:attachment].blank? && raw_request_body.blank?` returns **422**. Whitespace-only counts as blank.
  - A JSON body is **not** parsed; it would be posted literally.
  - Success: **201 Created**, empty body, `Location: message_url(@message)` = `/messages/:id`. That URL isn't dereferenceable (quirk).
  - Side effects: `broadcast_create` (room stream and unread fan-out), then `deliver_webhooks_to_bots`, excluding the sending bot.
- **GET messages** (index): `?before=<id>` (older page), `?after=<id>` (newer page), or default (last page).
  - Page size is 40 and messages are returned oldest to newest.
  - **200** JSON array of message objects.
  - Headers: `X-Total-Count: <room message count>`, and `Link: <.../rooms/:room_id/:bot_key/messages?before=<first.id>>; rel="next"` when older messages exist. In `after` mode the link is `?after=<last.id>` when newer messages exist. No `Link` header on the last page.
  - An empty room returns `[]`.
- **PATCH/PUT messages/:id**: raw body becomes the new body (or multipart `attachment`). **200** with the message JSON. **403** if the bot is not the creator (bots are never admins). **404** if the room isn't accessible or the message isn't in that room. Broadcasts a replace of the presentation.
- **DELETE messages/:id**: **204**, or 403 if not the creator. Broadcasts a remove.
- **POST messages/:message_id/boosts**: raw body becomes `boost.content`. **201** with the boost JSON. **422** if the body is blank. **404** if the room isn't accessible or the message isn't in that room. Broadcasts an append.
- **DELETE messages/:message_id/boosts/:id**: **204**. **404** if it isn't the bot's own boost. Broadcasts a remove.

**JSON shapes** (jbuilder):
```jsonc
// message (messages/_message.json.jbuilder)
{ "id": 1, "created_at": "2024-01-01T00:00:00.000Z",           // UTC, iso8601 ms
  "body": { "plain_text": "Hello", "html": "<div>Hello</div>" }, // plain_text = text || attachment filename || ""
  "creator": { "id": 2, "name": "Bender Bot", "role": "bot", "avatar_url": "https://…/users/<avatar_token>/avatar?v=…" },
  "room": { "id": 3 },
  "url": "https://host/rooms/3/messages/1" }
// boost (messages/boosts/_boost.json.jbuilder)
{ "id": 9, "content": "👀", "created_at": "…Z",
  "booster": { "id": 2, "name": "…", "role": "bot", "avatar_url": "…" },
  "message": { "id": 1, "url": "https://host/rooms/3/messages/1" } }
```

**Outgoing webhook** (`Webhook#deliver`, run by `Bot::WebhookJob`):
- **Trigger** (both web and bot `create`): in a **direct** room, every active bot member; otherwise, active bots that were **@mentioned**. The message creator is always excluded.
- **Request:** `POST <webhook_url>` with `Content-Type: application/json`, open and read timeouts of **7 s**, and no SSRF guard (the URL is admin-set).
```json
{ "user":    { "id": 1, "name": "David" },
  "room":    { "id": 3, "name": "Watercooler", "path": "/rooms/3/<bot_key>/messages" },
  "message": { "id": 7, "body": { "html": "<div>…</div>", "plain": "text minus @bot mention, trimmed" },
               "path": "/rooms/3/@7" } }
```
- **Reply handling:**
  - HTTP 200 with content type `text/html` or `text/plain`: the body is posted as a text message by the bot.
  - Any other content type that maps to a known MIME type: the body is posted as an attachment named `attachment.<ext>`.
  - A timeout posts the message "Failed to respond within 7 seconds".
  - Every reply calls `broadcast_create`.

## 4. Realtime (ActionCable)

### 4.1 Connection
`ApplicationCable::Connection` uses `identified_by :current_user`. It resolves the user from the `session_token` signed cookie, or rejects the connection. `User#reset_remote_connections` disconnects with `reconnect: true` (logout, membership destroyed). `close_remote_connections` uses `reconnect: false` (ban, deactivate). Adapter: Redis.

### 4.2 Channels

### 4.3 Presence semantics (`Membership::Connectable`)

`memberships.connections` (int) and `memberships.connected_at` track presence. `CONNECTION_TTL = 60.seconds`, so "connected" means `connected_at >= 60.seconds.ago`.

- **`present`** (on subscribe or when the tab becomes visible): `connections = connected? ? connections + 1 : 1`, `connected_at = now`, and **`unread_at = nil`** (marks the room read). It then broadcasts `{room_id}` to `user_#{id}_reads`, so every tab of that user clears the unread dot.
- **`absent`** (on unsubscribe or when the tab is hidden for 5 s): decrement `connections`. If it drops below 1, set `connected_at = nil`.
- **`refresh`** (the client sends it every 50 s while visible): bumps `connected_at` and re-increments if the membership had expired.

Why it matters: when a message is created, `Room#receive` does two things:
- `memberships.visible.disconnected.where.not(user: creator).update_all(unread_at: message.created_at)`. This drives the bold or unread state in the sidebar on page load.
- It enqueues web push to **disconnected** visible members, filtered by involvement: everything, or mentions when the user was @mentioned.

Client timing details: presence `present`/`absent` changes are debounced 5 s on `visibilitychange`. Typing `start` is throttled to once per 1 s. The client expires typing entries after 5 s.

### 4.4 Every server broadcast

DOM id note: `Message#to_key = [client_message_id]`, so `dom_id(message)` is `message_<client_message_id>`. This lets the sender's optimistic "pending" element (created with the same client id) be replaced in place.

| # | Trigger | Stream | Payload / Turbo action |
|---|---|---|---|
| B1 | Message created (web `messages#create`, bot create, webhook reply) → `Message#broadcast_create` | `[room, :messages]` | `append` to target `messages_<room>` with the full message partial |
| B2 | Same as B1 (`broadcast_unread_room`) | `user_<uid>_unreads` **for each member** (including the sender) | JSON `{"roomId": <id>}`. The client adds the `unread` class unless it is the current room, and reorders DMs. |
| B3 | Message updated (web or bot) | `[room, :messages]` | `replace` target `presentation_message_<cid>` with the `messages/presentation` partial (`maintain_scroll`) |
| B4 | Message destroyed (web or bot; also `remove_banned_content`) → `broadcast_remove` | `[room, :messages]` | `remove` target `message_<cid>` |
| B5 | Boost created (web or bot) | `[room, :messages]` | `append` to `boosts_message_<cid>` with the boost partial |
| B6 | Boost destroyed (web or bot) | `[room, :messages]` | `remove` target `boost_<id>` |
| B7 | Typing start/stop (client action) | `typing_notifications:<room>` | `{action, user: {id, name}}`. Clients ignore their own. |

### 4.5 Proposed Phoenix PubSub mapping

Design rule: **fan out per user for anything sidebar-related**. Skip the global `"rooms"` stream: in the original it carries open-room changes plus removals of *every* room type (only the DOM id leaks). One code path for every room type is simpler and uniformly secure. **Authorize at subscribe time**, meaning in LiveView `mount`/`handle_params` after checking membership.

| Original | PubSub topic | Message (`handle_info`) | Handler (LiveView) |
|---|---|---|---|
| B1 | `"room:#{room_id}"` | `{:message_created, message}` | `RoomLive`: `stream_insert(socket, :messages, msg)`. Stream DOM id is `"message-#{client_message_id}"`, so it replaces the optimistic or own copy. Play `/play` sound via `push_event`. |
| B3 | `"room:#{room_id}"` | `{:message_updated, message}` | `RoomLive`: `stream_insert` (replace) |
| B4 | `"room:#{room_id}"` | `{:message_deleted, %{id, client_message_id}}` | `RoomLive`: `stream_delete_by_dom_id` |
| B5/B6 | `"room:#{room_id}"` | `{:boosts_changed, message_id}` | `RoomLive`: reload the message with boosts and `stream_insert` it (simplest; avoids nested streams) |
| B7 | `"room:#{room_id}:typing"` | `{:typing, :start \| :stop, %{id, name}}` | `RoomLive` (or a typing LiveComponent): keep a map of name → timestamp and purge after 5 s with `Process.send_after`. The client hook pushes `"typing"` events, throttled to 1 s. The server uses `broadcast_from` so the sender is excluded. |
| B2 | `"user:#{user_id}"` | `{:room_unread, room_id}` | `SidebarLive`: mark unread unless it is the currently viewed room, and bump the DM ordering |
| B8 | `"user:#{user_id}"` | `{:room_read, room_id}` | `SidebarLive`: clear unread |
| B9/B12/B14/B16 | `"user:#{user_id}"` (fan out to the room's members, or all active users for an open room) | `{:room_added, room}` | `SidebarLive`: insert into the shared or direct list |
| B10/B13 | `"user:#{user_id}"` | `{:room_updated, room}` | `SidebarLive`: update; `RoomLive` updates the header if it is the same room |
| B11/B15 | `"user:#{user_id}"` | `{:room_removed, room_id}` | `SidebarLive`: remove. `RoomLive` viewing that room: `push_navigate(to: ~p"/")` with a flash. |
| B17 (membership revoked) | `"user:#{user_id}"` | `{:membership_revoked, room_id}` | `RoomLive`: if it is the current room, unsubscribe and navigate to `/`. `SidebarLive`: remove the room. This replaces "force reconnect". |
| B17/B18 (logout, ban, deactivate) | `live_socket_id = "users_sessions:#{session_token_hash}"` (one per session) or `"users:#{user_id}"` | `Endpoint.broadcast(live_socket_id, "disconnect", %{})` | Built-in LiveView socket kill. For a ban or deactivation, broadcast for every session of the user. |
| Presence (4.3) | `Phoenix.Presence` topic `"presence:room:#{room_id}"`, key = user_id | `presence_diff` (optional to handle) | `RoomLive` mount does `Presence.track(self(), topic, user_id, %{})` when connected. A JS hook on `visibilitychange` (5 s debounce) pushes `"visibility"` events, which `untrack`/`track`. On track, set `membership.unread_at = nil` and broadcast `{:room_read, room_id}` to `"user:#{uid}"`. On message create, the "disconnected" set is the visible members **not in** `Presence.list(topic)`; set `unread_at` for them. The `connections`/`connected_at` columns and the 50 s `refresh` ping can then be dropped. |
| Heartbeat + `/rooms/:id/refresh` | – | – | **Drop.** A LiveView reconnect re-mounts and re-fetches the last page. Use `phx-disconnected`/`phx-connected` bindings to disable the composer while offline. |

Notes for the Ash side: issue the broadcasts from Ash change `after_action` hooks (or `Ash.Notifier.PubSub`) on `Message.create/update/destroy`, `Boost.create/destroy`, `Room.create/update/destroy`, and `Membership.update(involvement)/destroy`. Keep the HTTP/LiveView layer free of broadcast logic so the bot API, webhook replies and the ban cleanup job emit the same events.

## 5. Recommended simple Phoenix design

### 5.1 Plugs and pipelines
- `:browser`: fetch_session, CSRF, `FetchCurrentUser` (Plug session `:session_token` → `sessions` row → user; refresh `last_active_at` hourly), `BlockBannedIP` (non-GET → 429).
- `:require_auth`: redirect to `/session/new`, storing `return_to`. `:require_guest`: redirect signed-in users to `/`.
- `live_session :authenticated, on_mount: [{CampfireWeb.UserAuth, :ensure_authenticated}]`. Also check the banned IP in on_mount, using `get_connect_info(socket, :peer_data)` / `x_headers`, because LiveView events don't go through the HTTP ban plug.
- Set `live_socket_id` so logout and ban can disconnect sockets.
- `:bot_api`: `accepts ["json"]`, no CSRF, no session, `BotAuth` plug (parse `:bot_key`, constant-time token compare, 401 on failure).
- **Raw body gotcha:** `curl -d 'Hello'` sends `application/x-www-form-urlencoded`, so `Plug.Parsers` in the Endpoint will **consume the body**. Configure `Plug.Parsers` with `body_reader: {CampfireWeb.CacheBodyReader, :read_body, []}`, which stashes the raw body in `conn.assigns.raw_body`, and read it from there in the bot controller. Multipart `attachment` arrives as `%Plug.Upload{}`. Force UTF-8; reject whitespace-only bodies with 422.
- Login rate limit: a small ETS or Hammer limiter (10 per 3 min per IP). Optional.

### 5.3 LiveViews and responsibilities
- **`SidebarLive`**: `live_render(..., sticky: true, id: "sidebar")` in the app layout so it survives `push_navigate` between rooms.
  - Subscribes to `"user:#{id}"` and shows shared rooms, direct rooms (sorted by `updated_at` desc), unread dots and the "new room" button (respects the restriction).
  - Receives the current room id through PubSub or `handle_params` messaging, or simply highlights from the URL via a JS hook. The simplest option: `RoomLive` broadcasts `{:viewing, room_id}` on `"user:#{id}"`.
  - Includes the DM placeholders (up to 20 users without a DM).
- **`RoomLive`**: header (name, edit link, involvement bell cycling), `stream(:messages)` with the last 40.
  - Infinite scroll up uses `phx-viewport-top` → `load_before`. Down (after an `@message` jump) uses `phx-viewport-bottom` → `load_after`.
  - Composer: text or rich text plus `allow_upload(:attachment, max_entries: 10, auto_upload: true)`. Each uploaded file becomes its own attachment message.
  - Keeps `client_message_id` for idempotent DOM ids and optimistic insert (a JS hook can insert a pending bubble; or skip optimism, since a LiveView round-trip is fast).
  - Inline edit (admin or creator), delete, boosts (quick emoji set plus a free-text form of up to 16 characters, delete own), typing indicator, presence tracking, `/play <sound>` messages.
- **`HomeLive`**: redirects to the `last_room` (store it in the session or a cookie via a controller hop, or in a `users.last_room_id` column, which is simpler under LiveView), else shows the empty state.
- **`RoomFormLive`**: create and edit for open and closed rooms (with conversion between them). Direct rooms get participants plus delete.
- **`DirectPickerLive`**: multi-select users → `find_or_create`.
- **`SearchLive`**: query form, recent searches (10), clear, results linking to `/rooms/:id/@:mid`.
- **`ProfileLive`**, **`UserLive`**, **`AccountLive`**, **`BotsLive`**: as listed above.

### 5.5 Subtle behaviors to preserve (checklist)
1. A bot key works only on whitelisted bot endpoints. Elsewhere, a bot gets 403 and is never treated as a session.
2. Bot endpoints return 404 (not 403) for rooms the bot isn't in, and for messages or boosts outside that room. They return 403 for editing or deleting someone else's message, and 404 for deleting someone else's boost.
3. Webhooks never fire to the bot that authored the message. They fire for DMs (all bots in the room) or @mentions (other room types).
4. Message DOM identity is `client_message_id`, generated server-side as a UUID when absent (bots).
5. Unread state: `unread_at` is set only for visible members who are not present, excluding the author. Becoming present clears it and syncs every tab of that user.
6. Revoking a membership must immediately stop delivery to that user's open room view (the original forces a reconnect). Subscribe authorization must re-check membership.
7. Closed-room creation doesn't auto-add the creator (the form pre-checks them). Open rooms auto-grant all active users, and new users auto-join all open rooms.
8. `Rooms::Direct.find_or_create_for` matches on the exact user set, which always includes the current user.
9. Deactivation keeps direct-room memberships (history stays visible to others) but removes the rest. Ban deletes all of the user's messages and broadcasts each removal.
10. A POST from a banned IP returns 429. GETs are still allowed.
