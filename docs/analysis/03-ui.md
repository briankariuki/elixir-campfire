# 03 — UI / Frontend layer analysis (Campfire → Phoenix LiveView + Ash)

Source: `basecamp/once-campfire` (MIT). Paths below are relative to the Rails repo root.
Stack today: Turbo (Drive, Frames, Streams over ActionCable), Stimulus (35 controllers), Lexxy rich-text editor (Lexical-based, replaced Trix), highlight.js, importmap (no bundler), Propshaft serving **plain modern CSS** (native nesting, `oklch()`, `:has()`; no Sass, no Tailwind). Every file in `app/assets/stylesheets/` is loaded via `stylesheet_link_tag :all`.

## 1. Page-by-page inventory

Conventions across the app:
- Every page sets `@page_title` and optionally `@body_class` (`"sidebar"`, `"signup"`, `"sidebar searches"`). Body also gets `admin` (when the user can administer) and `account-has-logo`.
- Pages fill three named slots in the layout: `:nav` (top bar), the main body, `:footer` (composer area), `:sidebar`.
- Icon-only buttons everywhere: `<a|button class="btn"><img src="x.svg" aria-hidden><span class="for-screen-reader">Label</span></a>` — the CSS makes any `.btn` containing `img` + `.for-screen-reader` a **round icon button** automatically.
- Settings pages use a centered card: `<section class="panel">` (`panel--wide` = 80ch). Nav has a back button (`link_back_to_last_room_visited` → arrow-left.svg).
- Next to most inputs is a "translate" globe `<details>` popup (`translation_button`) listing hard-coded translations of the label in 7 languages. **Drop in port.**
- Destructive actions use `data-turbo-confirm` (→ `data-confirm` in Phoenix).

    script[type=text/template] (pending-message template)
    div#room_<id>_messages.messages        (maintain-scroll / refresh-room)

- **System welcome** (`rooms/show/_invitation`): `div#system_welcome.message.message--formatted` with logo, "Welcome to Campfire — share the join link below", and the invite widget (`accounts/_invite`: readonly join URL input, QR code button, copy button, web-share button, admin-only "regenerate" button).
- **Footer**: the composer (section 5). Left of it, a round search button (search.svg → `/searches`).
- **Sidebar**: lazily loaded `turbo-frame#user_sidebar` (section 1.6).
- **Lightbox**: global `<dialog class="lightbox">` in the layout with image, close, download, share buttons.

### 1.9 Involvement / notifications bell (in room nav; also on profile membership list)
`rooms/involvements/_bell`: wrapper with `notifications` controller; initially a loading bell icon. Once push notifications are confirmed enabled, it lazy-loads `GET /rooms/:id/involvement` into a turbo-frame which renders `button_to PUT /rooms/:id/involvement?involvement=<next>` with class `btn <involvement>` and icon `notification-bell-<involvement>.svg`.
Cycle order — shared rooms: `mentions → everything → nothing → invisible → mentions`; direct rooms: `everything ↔ nothing`. Labels: "Notifying about @ mentions", "Notifying about all messages", "Notifications are off", "Notifications are off and room invisible in sidebar". If notifications aren't permitted, the bell shows an alert icon and clicking opens a `<dialog class="dialog">` with browser/OS-specific help (`pwa/_browser_settings`, `_system_settings`, `_install_instructions`). The bell pulses (`btn--pulsing`) on first run.
Port: render the toggle button directly (no lazy frame); show the push-permission prompt/dialog only if web push is implemented.

## 2. Layout structure & CSS

### 2.1 Layout skeleton (`layouts/application.html.erb`)
```html
<body class="sidebar admin account-has-logo">   <!-- body classes per page -->
  <a href="#main-content" class="skip-navigation btn">Skip to main content</a>
  <nav id="nav"> …:nav slot… </nav>
  <div class="flash">…</div>                     <!-- optional -->
  <main id="main-content">
    …page body (e.g. #message-area)…
    <footer id="footer"> …:footer slot (composer)… </footer>
  </main>
  <aside id="sidebar"> …:sidebar slot… </aside>
  <dialog class="lightbox">…</dialog>
  <a id="app-logo" href="https://once.com"><img src="campfire-icon.png"></a>
</body>
```
`layout.css`: body is a CSS grid `"nav sidebar" / "main sidebar"`, columns `1fr var(--sidebar-width)`, `max-block-size: 100dvh`. `--sidebar-width` is `0vw` by default and `26vw` when `body.sidebar` and viewport ≥ 100ch. Below 100ch the sidebar is `position:fixed` off-canvas (`transform: translate(100%)`), shown with `#sidebar.open`. `#main-content` is a flex column (`justify-content:end` in sidebar layout so messages stick to the bottom), with `margin-inline: 5vw 0` + side borders on desktop. `#nav` is `position:fixed` across the top (minus sidebar width), `pointer-events:none` (buttons re-enable). `.messages` is the scroll container (`overflow-y:auto`, grid of rows with `row-gap: var(--message-space)`); on mobile it gets top padding = `--navbar-height`.
Important: the **scroll container is `.messages`**, not the page. The footer/composer is a non-scrolling flex item below it.

Flash: `div.flash > div.flash__inner` — a round green (or red for alert) badge with a check/alert icon that animates in and fades (`appear-then-fade 3s`), text only for screen readers; removed on `animationend`. Map Phoenix flash `:info`/`:error` to this.

### 2.3 Key variables & utility classes the markup relies on
- Spacing: `--inline-space: 1ch`, `--inline-space-half/-double`, `--block-space: 1rem`, `--block-space-half/-double`. Layout: `--sidebar-width`, `--navbar-height: 4.125em`, `--footer-height`, `--btn-size: 2.65em`.

### 3.6 Pending (optimistic) messages

### 3.7 Pagination & live updates (behavior to reproduce)
- Room loads the **last page** of messages, scrolled to bottom. Scrolling to the top fetches `?before=<first id>` and prepends while keeping scroll position; if the view was opened at `/@id` (or messages were trimmed) scrolling down fetches `?after=<last id>` until up to date. DOM is trimmed to ~300 messages.
- New messages (broadcast append) auto-scroll only if the user was within 100px of the bottom; otherwise the "jump to newest" pulsing round button appears. Messages are inserted in `data-sort-value` order (handles out-of-order arrival).
- On websocket reconnect or tab visible after >60s hidden: `GET /rooms/:id/refresh?since=<max updated_at>` appends new and replaces updated messages. Composer is disabled after 5s offline.
- Port: LiveView `stream(:messages, …, at: -1)` for appends, `at: 0` for older pages + `phx-viewport-top` / `phx-viewport-bottom` bindings for infinite scroll, `stream(…, limit: -300)` for trimming; LiveView's reconnect remount replaces refresh-room.

### Minimal JS hooks for the port (~150 lines total)
1. **`MessageList`** (on `.messages` container): on mount scroll to bottom (or center the highlighted `/@id` message); `beforeUpdate` record `scrollHeight`/whether near bottom (≤100px); `updated` → if was near bottom scroll to bottom, else if items were prepended preserve offset, else show "jump to newest" button; on new message containing `.sound` → play it; optionally recompute `message--threaded` / `message--first-of-day` for changed boundary items.
2. **`Composer`** (on textarea): Enter submits (Shift+Enter newline; ignore during IME composition and when mention menu open; on touch devices Enter = newline), auto-grow height, Up-arrow on empty → `pushEvent("edit_last")`, refocus + clear after submit (`handleEvent("composer:reset")`), optional localStorage draft per room.

5. **`Lightbox`** + **`Copy`**: tiny dialog opener and clipboard writer (or global `window.addEventListener("phx:…")` handlers).
6. (optional) **`Notifications`**: browser `Notification` permission + service worker for Web Push.

- **Plain `<textarea name="message[body]" rows=1>`** inside the same `div.composer__input.input.input--actor` wrapper (keep classes so CSS still applies; give it `class="input"` and `phx-hook="Composer"`). Auto-grow to a max height (~10 lines) via the hook.
- **Body storage**: store plain text (or minimal markdown). Render on the server: HTML-escape → convert URLs to `<a target=_blank rel=noopener>` → newlines to `<br>`/paragraphs → optionally a tiny markdown subset (`**bold**`, `_italic_`, `` `code` ``, ``` ``` ``` fenced blocks → `<pre>`, `> quote` → `<blockquote>`) using a sanitizing Markdown lib (Earmark + HtmlSanitizeEx, or MDEx). Wrap in `<div class="lexxy-content">` (or rename to `.message-content` and adjust `actiontext.css` selectors) to reuse typography.
- **Mentions**: store as `@Name` text; at save time resolve `@Full Name` against room members (longest match) and persist mention user ids (needed for notifications + `message--mentioned`). Render as `<span class="mention" data-user-id="ID"><img class="avatar" …> Name</span>` for the same look. **Stretch**: `@` autocomplete — hook detects `@word` at the caret, `pushEvent("mention_search", q)`, LiveView renders a small `ul` popover (reuse `.autocomplete__list/.autocomplete__item` styles), Enter/Tab/click inserts `@Full Name `; Enter-to-send must be suppressed while the menu is open.
- **Sound commands**: detect `^/play (\w+)$` on the server exactly as today (no client parsing needed).
- **Replies**: Reply action pre-fills the textarea with `> quoted line(s)\n— Author #link\n\n`; render `>` lines as `<blockquote>` and the attribution as `<cite>`.
- **Attachments**: `allow_upload(:attachments, accept: :any, max_entries: 10, max_file_size: …, auto_upload: true)`, `<.live_file_input>` inside the existing `label.btn.composer__attachment-btn.input--file` (keeps the paperclip look), `phx-drop-target` on `#message-area` and the composer, chips rendered from `@uploads.attachments.entries` with `<.live_img_preview>` in `.composer__file-thumbnail`, progress via `entry.progress` → `style="--percentage: N%"`. Drop the rich text toolbar button.
- **Drafts**: optional (hook + localStorage), low priority.
- **Typing**: `phx-change` on the form with `phx-debounce`/throttle, or the hook pushes `typing` events at most once/second and `stop_typing` on submit/blur; LV broadcasts to room topic; indicator rendered from a map of `name => last_seen` with a 5s expiry timer.
